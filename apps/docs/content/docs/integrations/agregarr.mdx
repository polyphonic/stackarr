## Guided setup

When Agregarr is enabled, `stackarr configure` uses Agregarr's native API to reuse the signed-in Plex owner, connect the enabled Radarr and Sonarr services, save Agregarr's generated API key, and finish initialization. Agregarr itself uses Plex authentication; its current upstream release does not expose a supported local-password setup flow.

Stackarr also creates or normalizes a **Coming Soon** source for the enabled movie and TV libraries. The source:

- is the default Agregarr source created during Stackarr onboarding;
- includes every monitored, missing Radarr movie with release-date metadata inside the configured window, regardless of which quota-approved Pulsarr user requested it;
- includes monitored Sonarr shows only when the official Agregarr release can find a future, monitored, undownloaded season premiere (`SxxE01`);
- creates placeholders for titles that have not reached Plex yet;
- sorts soonest-first using Agregarr's availability-aware release date logic; and
- appears on Plex Home and each library's Recommended screen by default.

Stackarr promotes a **New Releases** row with up to 30 items to the first position for each enabled movie and TV library. It keeps Plex's release-hub behavior—movies are sorted by release date and TV shows by their most recently aired episode, newest first from left to right—but uses Agregarr's filtered smart-collection equivalent so Coming Soon trailer placeholders never leak into the row. Existing **Recently Added** rows remain enabled and retain their relative position behind New Releases.

Stackarr applies a fail-closed startup guard for an Agregarr 2.4.2 cleanup bug that otherwise removes still-desired placeholders after seven days. The guard keeps the official image, limits age-based cleanup to items that have actually left the current source, and avoids duplicating a year already present in a TV title's placeholder folder. If a future image changes the affected code in an unrecognized way, Agregarr stops before scheduling work instead of risking a destructive collection sync.

Agregarr reads Radarr and Sonarr directly, so it does not distinguish between the Plex owner and quota-approved Pulsarr users. Pulsarr must route the title as monitored: an unmonitored Arr entry is intentionally excluded. For TV, future non-premiere episodes do not currently qualify in the official Agregarr image. Stackarr does not patch or replace that image to broaden the filter.

For placeholder-backed collections, Stackarr configures Agregarr's supported per-library roots as `_Trailers` subfolders inside the Plex movie and TV libraries. The leading underscore keeps the folder near the top of a file browser. Change **Apps → Agregarr → Placeholder Folder** when another single folder name is preferred. Stackarr keeps the trailers visible to Plex, outside the Arr-managed title folders, and adds the same folder name to tinyMediaManager's native `skipFolder` lists.

Because Plex's built-in Recently Added and Recently Released hubs do not understand Agregarr's placeholder label, they can show trailer entries as ordinary media. During onboarding, Stackarr uses Agregarr's native filtered-hub source to replace any affected visible default hubs, copies their Home and Recommended visibility to the replacements, and hides the originals. The Recently Released replacements are named **New Releases**, fixed at the top, and never randomized. This resolves Agregarr's **Filtered Hubs Recommended** warning without modifying its image.

Movie ordering prefers the earliest known digital or physical date. When neither is available, Agregarr estimates availability from the theatrical date. Plex may still display the theatrical date on the item card, so the visible date can differ from the availability date used for ordering.

Plex collections belong to a single library, so a movie and TV collection cannot be one physical Plex object. Stackarr creates linked rows for both libraries. Manage their presentation in Agregarr itself, or use Stackarr's bounded CLI and MCP commands for agent workflows.

## Everyday controls

Stackarr deliberately does not duplicate Agregarr's collection editor in the dashboard. Open Agregarr from **Apps** for its full UI, or use these host CLI commands:

```bash
stackarr agregarr overview
stackarr agregarr collection <collection-id>
stackarr agregarr home-order
stackarr agregarr sync <collection-id>
stackarr agregarr sync-group <movie-id> <tv-id>
stackarr agregarr ensure-preset coming-soon --media-scope both
stackarr agregarr update-group <movie-id> <tv-id> --show-on-home true --recommended true
stackarr agregarr job quick-sync
```

The same bounded operations are available to trusted MCP clients as:

- `stackarr_get_agregarr_overview`
- `stackarr_get_agregarr_collection`
- `stackarr_get_agregarr_home_order`
- `stackarr_sync_agregarr_collection`
- `stackarr_sync_agregarr_collection_group`
- `stackarr_ensure_agregarr_collection_preset`
- `stackarr_update_agregarr_collection_group`
- `stackarr_run_agregarr_job`

Write operations require an MCP profile with `apps:write` authority. Stackarr validates collection IDs, presets, jobs, and every mutable option before forwarding the request to Agregarr.

Existing handmade Plex collections remain pre-existing and are not adopted automatically.
