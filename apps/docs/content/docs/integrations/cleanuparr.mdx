# Cleanuparr

[Cleanuparr](https://github.com/cleanuparr/cleanuparr) monitors download clients and Arr applications for unwanted or unsafe file patterns. Stackarr keeps its dashboard bound to loopback by default and can configure it automatically when at least one of Radarr, Sonarr, or Lidarr is enabled.

## Stackarr defaults

When **Cleanuparr Download Security** is enabled, Stackarr:

- starts the official Cleanuparr image in the managed Compose project;
- connects the selected Transmission or qBittorrent client;
- connects each enabled Radarr, Sonarr, and Lidarr instance;
- writes a local media-focused malware blocklist under the Cleanuparr config directory; and
- scans every five seconds by default using `CLEANUPARR_MALWARE_CRON`.

The blocklist rejects executable, script, shortcut, macro-document, installer, package, and disk-image patterns such as `.exe`, `.lnk`, `.ps1`, and `.dmg`. Ordinary video, audio, subtitle, image, and metadata files are not blocked merely because they are inside the same download.

Cleanuparr deletes the complete download when any included file matches a blocked pattern. Review its history after enabling it and adjust the managed schedule or disable auto-configuration if your library intentionally contains software images or other blocked file types.

Cleanuparr is not a virus scanner. For Questarr-to-RomM imports, Stackarr uses ClamAV as a fail-closed antivirus gate before any file reaches the game library. Cleanuparr remains defense in depth for executable/script patterns and can inspect non-game downloads because Stackarr enables processing for downloads without an Arr content ID.

The dedicated `games` category is excluded from Cleanuparr's media-oriented extension blocklist because valid retro payloads commonly contain `.iso` and other disk images. Those downloads remain gated by ClamAV before Stackarr imports them into RomM.

## Dashboard settings

Use **Apps → Cleanuparr → Settings** to change the loopback URL, port, image, automatic configuration, or malware scan schedule. Changes consumed by the container automatically queue a targeted Cleanuparr recreation; the rest of the stack remains running.

The configuration and blocklist are included in Stackarr backups. Downloaded media and active torrent payloads are not.
