# Storage Paths

Choose the mounted logical volume, whether it is one drive or a software RAID mirror. Do not select RAID member disks. Stackarr does not create or format RAID arrays. Redundancy is not a backup.

App data can remain on an SSD while Media lives on a hard drive or mounted RAID volume. Put downloads and transcode scratch below the same Media folder when you want same-mount imports. A separate download disk is supported, but imports then copy bytes. Shared folder names, matching device labels or a storage pool alone do not prove hardlink support: permissions, filesystem boundaries and application behavior still matter.

Stackarr separates media, downloads, config, state, logs, and backups. On a new installation, choose one host **Media folder**. The shared layout mounts that folder at `/data` inside media apps; the movie and TV folders are `Movies` and `TV Shows` relative to Media, not separate host roots.

For example, choosing `/srv/Media` gives host paths `/srv/Media/Movies` and `/srv/Media/TV Shows`. Apps use `/data/Movies` and `/data/TV Shows`. The `/data` path is an internal mount, not a folder to choose on the host.

Existing installations without `MEDIA_PATH_LAYOUT=shared` keep their legacy paths. Stackarr does not move files, rewrite saved roots, or switch the layout automatically. Review mounts and library paths before any deliberate migration.

A shared import root reduces actual Docker mounts, not just entries in the dashboard. Keep narrower mounts when an app does not need the whole tree: Agregarr receives the movie and TV libraries at `/data/Movies` and `/data/TV Shows`, without access to downloads or scratch. Separate disks, app configuration, and read-only versus writable folders remain distinct mounts. Grouping game libraries in an app does not require moving their files or granting writable access to the whole Games folder.

For removable disks, use [External Drives and Safe Migration](/docs/setup/external-storage). It covers volume-identity checks, guarded startup, offline config migration and rollback. Changing a path alone does not install these protections.

| Variable | Purpose |
| --- | --- |
| `MEDIA_ROOT` | Host Media folder. Shared layout mounts it at `/data`; movie and TV folders are relative to it. |
| `MEDIA_PATH_LAYOUT` | `shared` for the new direct layout; `legacy` (or absent on existing installs) keeps existing mounts. |
| `MUSIC_ROOT` | Music library root mounted read-only into Lidarr as `/music`. |
| `DOWNLOADS_ROOT` | Completed/incomplete/download-client folders. New installs default to a Downloads folder within Media; an independent host path remains available. |
| `APP_ROOT` | Stackarr application config root. |
| `CONFIG_ROOT` | Service configuration directories. |
| `STATE_ROOT` | Runtime state and generated files. |
| `LOG_ROOT` | Stackarr and helper logs. |
| `BACKUP_ROOT` | Backup archives. |

Keep download activity outside the scanned movie and TV folders. A `Media/Downloads` sibling of `Movies` and `TV Shows` keeps both on one filesystem for hardlinks while keeping incomplete files out of the libraries. An independent downloads folder is supported, but if it is on another filesystem, Arr imports copy rather than hardlink and consume additional space. Keep any existing downloads path unless you plan and verify a migration; editing a path does not move files.

### Transmission incomplete paths

Transmission 4.1.3 has one **session-wide** incomplete directory. With the
Stackarr preset, new unfinished Sonarr and Radarr torrents both stage under
`/data/Downloads/incomplete`; after completion, their Arr category selects
`/data/Downloads/complete/tv-sonarr` or `/data/Downloads/complete/radarr` respectively
in the shared layout (legacy installations retain `/downloads`)
(or the configured category names). A category/label or per-torrent
`download-dir` does **not** override the incomplete directory. Creating
`incomplete/tv-sonarr` and `incomplete/radarr` alone does not route bytes there.

Do not use an added/done script to move active torrents. It can race piece
writes, break resume/import, and displace Stackarr's unsafe-payload hook. To
require distinct incomplete paths, use independently configured Transmission
instances (one per Arr category), each with its own config, RPC port, incomplete
and complete directory, and preserved malware hook; this needs a separate
multi-instance integration. Until then, retain the shared incomplete directory
and completed category routing. Changing paths is forward-only: inspect active
torrents before rollout and do not relocate existing torrents automatically.

Lidarr is configured as a music acquisition helper. It can send releases to the selected download client, but completed Lidarr downloads stay in the downloads folder so you can review, retag, convert, and add them to your source music library manually.


## Folder-organized videos

New Youtarr installs use `${MEDIA_ROOT}/Videos/YouTube` by default. To expose multiple video categories through one Plex **Other Videos** library, point that library at `${MEDIA_ROOT}/Videos` and use Plex's Folder view. Each direct child becomes a top-level category, for example:

```text
Videos/
├── Music Videos/
└── YouTube/
```

Youtarr can continue targeting the same Plex library ID after its library location is broadened from the `YouTube` child to the `Videos` parent. Its output path and container mount do not need to change. Agregarr collections are not required for this filesystem-backed organization.

The same `Music Videos` folder can also be configured as Plex's global music-video path. When a file should appear both as a Music artist extra and as a standalone item in the generic Videos library, omit the optional `-video` suffix (for example, `Artist/Track Title.mp4`). Plex treats an untyped global music video as a regular music video, while the generic video scanner can index it as a standalone item.

To group those standalone items by artist in Plex, set each MP4's embedded `album` tag to the artist name. This mirrors Youtarr's channel metadata: Plex's Personal Media agent maps the shared album value to a collection, while `Music Videos` remains a filesystem category visible in Folder view. The portable layout is therefore:

```text
Videos/                         # Plex Other Videos library root
├── Music Videos/            # Folder-view category, not a collection
│   └── Artist/Track.mp4    # album=Artist creates the artist collection
└── YouTube/                 # Youtarr category; album=Channel is written by Youtarr
```

Agregarr is not required for these path-backed categories or embedded-metadata collections. Tag files before their first Plex scan when possible. After retagging an existing item, use **Refresh Metadata** on that item so Plex rereads the MP4.

After broadening an existing Plex library location from a child folder to `Videos`, run **Scan Library Files** once. Plex's automatic scanner depends on operating-system filesystem notifications; if it does not observe the newly configured root, restart Plex during a maintenance window to register a fresh watcher. The scheduled scan remains the fallback between manual scans.
