# Manage your homelab from chat

Stackarr is a local-first control plane that lets trusted AI agents set up and operate your homelab through consistent, typed actions. Use Codex, Claude, Hermes, OpenClaw, LM Studio, or another MCP client to manage requests, downloads, libraries, backups, containers, and remote access from the conversation you already use.

The dashboard is optional, not removed: it shows the same control plane and remains available whenever you want to inspect activity, intervene, or work manually.

<div className="calloutWarning"><strong>Alpha release:</strong> keep Stackarr and its stdio MCP server local. Start agents in <code>manage</code>, review approval prompts for disruptive actions, and avoid stop, update, or restart actions while Plex or Jellyfin must stay uninterrupted.</div>

## Start with an agent

1. [Install Stackarr](/docs/installation) natively or with Docker.
2. Connect the local MCP server or install an agent plugin.
3. Start with the `manage` authority profile.
4. Ask: **“Inspect my Stackarr setup, recommend the next step, and ask before making disruptive changes.”**

For Codex and other clients that can launch a local stdio MCP server:

```bash
codex mcp add stackarr \
  --env STACKARR_MCP_PROFILE=manage \
  -- stackarr mcp serve
```

For the bundled Hermes and OpenClaw integrations:

```bash
stackarr plugins install hermes --profile manage
stackarr plugins install openclaw --profile manage
```

<div className="calloutInfo"><strong>Want full autonomy?</strong> Launch with <code>STACKARR_MCP_PROFILE=unrestricted</code>. This deliberately removes per-action approval prompts. The agent cannot promote its own authority; only the person configuring the client can change the profile.</div>

## Supported Install Targets

| Target | Use When |
| --- | --- |
| macOS source/app archive | Plex or Jellyfin already runs natively and you want Stackarr to monitor/configure around it. |
| Linux archive + systemd installer | You want the classic arr app layout with app files in `/opt/Stackarr` and data in `/var/lib/stackarr`. |
| Windows package + Inno installer | You want to test the native dashboard package while Docker remains the supported Windows alpha backend. |
| Docker compose service | You want Stackarr and the managed services to start together. |

## Docker fast path

```bash
docker pull polyphonic/stackarr:alpha
docker compose -f stackarr/docker-compose.yml --profile stackarr up -d app
```

Open `http://127.0.0.1:7777/setup`.
