# Settings Storage

**Media Management** shows the host Media folder. In the shared layout, `Movies` and `TV Shows` are relative folders inside it. The container path `/data` is an internal mount, not a host folder. Existing installations without a shared layout retain their saved paths and mounts. Changing a field saves a path; it does not migrate existing files or convert the layout.

Downloads may be a `Downloads` folder inside Media or a separately chosen host folder. If downloads and Media are on different filesystems, imports copy files rather than hardlinking. Review mounted paths and data before applying any storage changes. Music, archive, and backup paths remain separately configurable.

Stackarr uses a split similar to the arr apps' app-data approach.

| Location | Purpose |
| --- | --- |
| Stackarr runtime database | Saved setup, paths, ports, install modes, UI, connection choices, tasks, notifications, and agent/audit activity. SQLite is the default; shared Postgres is available through advanced setup as `stackarr-main` plus `stackarr-log`. |
| `.stackarr/config/stackarr.db` | Default SQLite store and bootstrap/import source for installs that later move Stackarr settings to Postgres. Once Postgres is active, writes go to Postgres instead of mirroring a second live copy. |
| `.stackarr/config` | Service configuration plus naming, download, and request presets. |

Cloudflare token state files let the container scheduler run tunnel tasks outside the dashboard process. Dashboard-saved tokens remain the source of truth.

The Docker image never bakes local config, database files, logs, state, or token files into the image.

External application storage is an opt-in host operation, not an ordinary path-field edit. After host enrollment and controller recreation, **Settings → Media Management → Move configuration** queues the verified move through the internal host monitor. The controller reconnects after copying and restart, and the original remains available for recovery. Use the [external-storage workflow](/docs/setup/external-storage) for preparation and recovery. Internal-only installations remain unchanged.
