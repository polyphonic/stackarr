# Download Clients

Download Clients controls the active torrent client and shared download defaults.

## Transmission

Transmission is the default simple path and uses Stackarr-managed categories/folders.

## qBittorrent

qBittorrent is available as an alternative profile.

## Active Client

Only the selected torrent-client profile should be active. This avoids port conflicts and duplicate torrent state.

## Early DCP Movie Releases

Stackarr lets Radarr and supported request managers accept movies from the `inCinemas` availability point. A `DCP Rip` custom format strongly prefers release titles that explicitly identify a Digital Cinema Package, while `Non-DCP HDTV` rejects ordinary HDTV releases that do not identify DCP content.

The safeguards apply to the HD, HD Lite, and Any movie profiles and to their optional 4K equivalents. Stackarr does not treat every HDTV upload as an early cinema-quality release: the release title must match the bounded DCP expression before the positive DCP score can outweigh the HDTV rejection score.

## Download Provenance

Radarr and Sonarr remain the source of truth for grab and import history. Their history records the release title, indexer, download client, quality, and imported path.

Stackarr attempts to archive client `.torrent` metadata for Arr-triggered grabs when the client state file is available. It keeps a hash-keyed capture under `TORRENT_ARCHIVE_ROOT/_Unresolved/{radarr,sonarr}/` for import retries. On import, it also places the exact torrent under the movie or show directory named by Arr. Whole-torrent metadata determines TV placement: a single episode or single-season pack uses Sonarr's configured season folder, while a multi-season pack goes directly in the show folder. Shows without season folders remain flat. Ambiguous torrents stay unresolved. Safe release filenames are retained, with a hash suffix only for collisions and byte-bounded truncation for filesystem limits.

An adjacent `.provenance.json` starts with the successful import and is reconciled against the current library. It includes allowlisted Arr IDs, release title, indexer, client, torrent hash, quality and import paths, never download URLs or credentials. After an upgrade, the controller verifies the new file ID and exact imported path against native import history before replacing the current source association. A season or multi-season pack remains current while any library file still uses it. Verified obsolete sources and duplicate copies move into the private `.retired` directory for reversible recovery, rather than remaining alongside current sources. Torrent bytes are preserved, not rewritten to describe a different release. Reconciled sidecars contain the full `currentReferences` list, not only the first episode imported from a pack.

Retirement fails closed if any current file has unknown ownership, a replacement torrent is missing, imports are pending, paths have changed, or the library snapshot cannot be verified. Legacy files without sufficient history remain untouched. Standard and 4K instances have separate event identities; automatic retirement is held when 4K instances share the physical library until a joint ownership snapshot is available.

Transmission saves real metainfo after magnet metadata is complete. A separate controller worker polls client state independently of backup/update jobs, verifies the raw torrent infohash, and captures original bytes in the private `.metadata/_Captured` cache. Arr import hooks can use that cache after the download client removes its state. This closes the gap between the initial grab and import events, without replacing malware hooks or creating a new download. Capture is still best-effort if metadata is never obtained or a torrent is added and removed entirely between checks. Private working directories are not the current-library view.

After updating Stackarr, run `stackarr configure --archive-hooks` to refresh only the archive hook, classifier, per-instance Sonarr naming snapshots, and existing archive notifications. It does **not** reapply unrelated Arr preferences. The standard and 4K Sonarr instances read their own naming endpoints. The classifier uses the shell, `od`, and `awk` already present in the supported Arr images, without installing Python or downloading runtime packages. Rerun this narrow command after changing Sonarr's naming settings.

The archive defaults to `STATE_ROOT/torrent-archive`, independently of `CONFIG_ROOT`. Set **Torrent Archive Root** during setup or under Settings → Stackarr → Storage (`TORRENT_ARCHIVE_ROOT` for advanced configuration). Use an absolute host path outside managed config, log, backup, and staging trees. External macOS paths require storage-policy enrollment and host mount verification. Saving this setting does not migrate files or restart the stack. Back up, move and checksum-verify existing torrents and sidecars before applying the new mounts to the affected Arr services. The controller's archive bind also needs a separate refresh for provisioning, restore, and custom-root backup coverage. Verify task completion and actual bind paths, not merely a queued response.

Relocated `CONFIG_ROOT` supplies the hook and downloader-state binds; `STATE_ROOT` remains separate. Before Compose `up` or `create`, Stackarr refuses a cutover when a populated legacy `APP_ROOT/config/<service>` or `APP_ROOT/state/torrent-archive` would point to an empty destination. It does not move files; migrate and verify the data first, or retain the existing physical location through the installed storage-relocation symlink. A nonempty destination only clears this empty-target safety check, not a checksum verification of migrated contents. Custom host media roots still use `/movies` and `/tv` inside Arr. Unrecognized library paths remain unresolved. Backups include the configured archive; restore reports the archived source and current destination before changes, with `--torrent-archive-root` available for an explicit destination. Existing legacy archive trees are preserved rather than silently merged or deleted. Reconcile them using verified catalog matches and exact torrent checksums.

Use `stackarr_get_movie_download_provenance` with a Radarr movie ID. Use `stackarr_get_episode_download_provenance` with a Sonarr episode ID. Both tools join native grab and import history while excluding source URLs and credentials.
