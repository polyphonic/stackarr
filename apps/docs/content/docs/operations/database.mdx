# Database

Stackarr can run one shared Postgres service named `database` for Stackarr runtime config and apps that support external Postgres configuration.

Stackarr initializes those shared databases by executing the checked-in `database-init.sh` script inside the running `database` container. It does not keep a separate `database-init` sidecar container around.

The database image defaults to `timescale/timescaledb-ha:pg18.1-ts2.25.0`. It is a PostgreSQL 18 image with TimescaleDB and pgvector available, covering Tracearr's time-series tables plus Immich and BookOrbit vector search. Avoid `latest` tags for database images.

By default, onboarding uses `app-default` database mode. In that mode Stackarr keeps legacy Arr services on their native database choice, and the database container is only started when an enabled service requires it, such as BookOrbit, Immich, RomM, or Tracearr.

Advanced onboarding can switch to `postgres` mode. In that mode Stackarr creates separate logical databases and users for enabled supported apps:

- `bookorbit`
- `immich`, only when Immich is enabled, with `cube`, `earthdistance`, and `vector` enabled by default
- `romm`, only when RomM is enabled
- `stackarr-main` for Stackarr runtime settings, tasks, and notifications
- `stackarr-log` for Stackarr agent/audit activity
- `prowlarr-main` and `prowlarr-log`
- `sonarr-main` and `sonarr-log`
- `radarr-main` and `radarr-log`
- `lidarr-main` and `lidarr-log`
- `bazarr`
- `pulsarr`
- `seerr`, only when Seerr is enabled
- `tracearr`, only when Tracearr is enabled, with `timescaledb` enabled

Plex is not part of this shared Postgres setup and stays on its native database and config paths. Immich, RomM, and Tracearr use the shared Redis service when enabled.

The legacy single database named `stackarr` is not created by current onboarding. New shared-Postgres installs use `stackarr-main` and `stackarr-log`.

The database listens on internal container port `5432`. For host tools such as TablePlus, Stackarr publishes it on `127.0.0.1:5433` by default to avoid colliding with a local Postgres install.

## Initialize

```bash
bin/stackarr database ensure
```

The command starts the `database` container and reruns Stackarr's idempotent bootstrap for users, databases, privileges, and required extensions.

## Connection Strings

Use the password you set as the global admin password during onboarding. Stackarr stores the real value in runtime configuration; docs and source should use placeholders.

```text
postgresql://stackarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/stackarr-main
postgresql://stackarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/stackarr-log
```

Service database names follow the same pattern:

```text
postgresql://sonarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/sonarr-main
postgresql://radarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/radarr-main
postgresql://lidarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/lidarr-main
postgresql://prowlarr:<GLOBAL_ADMIN_PASSWORD>@127.0.0.1:5433/prowlarr-main
```

Use `bin/stackarr db-info` or the Stackarr UI to print the active redacted connection details for the current install.

## Backups

Stackarr backups include the pieces needed to restore the managed stack. When Postgres mode is enabled, backups include database dumps from the shared `database` container. Lite mode excludes rebuildable logs, caches, generated cover art, old app-internal backups, and other bulky data that the apps can recreate. Full mode includes more runtime metadata and can be much larger.

Plex stays outside the shared Postgres setup for upstream compatibility. Stackarr backs up Plex according to the selected backup mode and configured Plex paths. RomM state lives in its logical database inside the shared Postgres container, while its library, assets, config, and fetched resources stay on the configured filesystem paths.
